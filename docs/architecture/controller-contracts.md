# Controller contracts (M1 build specification)

> **Status (v0.1 release): experimental, partly built.** This document specifies the controller that the design package called for. In the v0.1 release the product is the agent, skill and workflow files; the controller is not connected to either host and has no command-line interface.
>
> | Module | State |
> |---|---|
> | `validation`, `storage`, `registry`, `policies`, `lineage`, `decisions`, `routing`, `receipts` | implemented, unit-tested (512 tests at release) |
> | `controller` | incomplete: `case_init`, `run_start`, `run_plan` only; untested |
> | `reporting`, `cli`, `fixture_runner`, `doctor` | not built |
> | `adapter_compiler`, `installer` | replaced by `tools/build_adapters.py` and `install.py` |
>
> Adversarial acceptance reviews (AT-06 to AT-16) and host conformance runs were not performed.

This document fixes the module boundaries, data model, schemas, state machines and policy checks that `src/ai_product_team/` implements. It is derived from `docs/spec/02_ARCHITECTURE.md` §§5–16 and `docs/spec/01_INITIAL_PRD.md` §§8–10, and it is the authority for M1 code. Where this document is silent, follow the architecture. Where the two disagree, this document wins and the disagreement is logged in `divergences.md`.

**Non-negotiables for every module**
- Python ≥ 3.11, standard library only. No network access. No third-party packages.
- Every public function has a docstring and type hints. Module-level docstring states the module's single responsibility.
- The controller never decides whether evidence is persuasive. It checks structure, references, versions, authority, independence and transitions.
- Nothing in this package publishes, deploys, sends, pays or deletes production data. There is no code path for an R3 action.
- A command named in a response is **not** a command that ran. Only `receipts.py` produces execution evidence.
- Mock, replay, native and sequential modes are distinct labels and are never merged.
- Errors are exceptions from `errors.py`; the CLI maps them to exit codes and JSON error objects. No bare `assert` for runtime validation.

### Exceptions (`errors.py`)
```
AiptError(Exception)                      base; .code (str), .details (dict)
  ValidationError    code="validation"    schema/reference failures; .errors: list[str] of JSON-pointer paths + messages
  NotFoundError      code="not_found"
  ConflictError      code="conflict"      stale expected_state_version; idempotency replay with different payload
  TransitionError    code="transition"    illegal state change
  PolicyError        code="policy"        authority, independence, version-binding, write-scope, protected-scope violations
  BudgetExhausted    code="budget"        admission refused; .partial_state summary
  ExecutionError     code="execution"     receipts: command could not start (not a nonzero exit — that is a result, not an error)
```

### IDs (`ids.py`)
`new_id(prefix)` → `f"{prefix}_{base32(os.urandom(16)).lower().rstrip('=')}"`. Prefixes: `case`, `run`, `task`, `disp`, `node`, `ver`, `edge`, `evt`, `rcpt`, `imp`, `wo` (work order). `sha256_bytes(b) -> str`, `sha256_json(obj) -> str` (canonical: `json.dumps(obj, sort_keys=True, separators=(",", ":"), ensure_ascii=False)`).

Timestamps: ISO-8601 UTC with `Z`, generated by a single `now()` in `ids.py` that tests can monkeypatch.

## 2. `validation.py`

```python
def load_schema(name: str) -> dict                 # schemas/<name>.schema.json, cached
def validate(instance, schema: dict, *, root: dict | None = None) -> list[str]
def ensure_valid(instance, schema_name: str) -> None  # raises ValidationError with all errors
```
Supported keywords (and nothing else; a contract test `tests/contracts/test_schema_subset.py` scans every schema and fails on an unsupported keyword): `$schema`, `$id`, `title`, `description`, `$defs`, `$ref` (local `#/$defs/...` and `#/...` only), `type` (string or list; `integer` distinct from `number`), `properties`, `required`, `additionalProperties` (bool or schema), `enum`, `const`, `items` (schema), `minItems`, `maxItems`, `uniqueItems`, `pattern` (Python `re.search`), `minLength`, `maxLength`, `minimum`, `maximum`, `format` (recorded, not enforced, except `date-time` which must parse), `oneOf`, `anyOf`, `allOf`, `not`, `default` (ignored), `examples` (ignored). Error strings: `"<json-pointer>: <message>"`, e.g. `"/status: 'done' is not one of ['complete', ...]"`.

## 4. `registry.py`

```python
@dataclass(frozen=True) class Agent / Skill / Workflow / Stage / Team   # fields mirror the JSON

    @classmethod load(root: Path) -> Registry          # reads registry/{agents,skills,workflows}.json
    def validate() -> list[str]                        # all issues, empty when valid
    agents: dict[str, Agent]; skills: dict[str, Skill]; workflows: dict[str, Workflow]  # workflows keyed by id AND name
    teams: dict[str, Team]
    def skill_used_by(skill_id) -> list[str]            # derived
    def manager_of(agent_id) -> str | None; def director_of(agent_id) -> str | None
    def reporting_chain(agent_id) -> list[str]          # up to human-owner

```
`validate()` must report: schema failures per record; duplicate ids; exactly 64 agents, 11 teams (leadership 4 + ten of 6); every `reports_to`/`reviewed_by` resolves to an agent id or `human-owner`; no cycle in `reports_to`; every manager's team members report to that manager; every `skill_ids` entry exists in skills.json; every skill referenced by at least one agent; every workflow stage role resolves (or is `proposal-owner` with `role_binding`); every `conditional` is a known predicate; every `conditional_specialists` entry resolves; every `manager` is a manager-type agent (or `adversarial-orchestrator`/`review-manager`/`audit-manager` as the spec assigns); `entry_skill` == `aipt-<name>`; **missing role body or skill directory is reported as `not_authored`, not as a hard failure** (M1 runs before M3 authors them).

## 5. `storage.py` and `schema.sql`

```python
class CaseStore:
    def __init__(self, case_dir: Path)                 # case_dir/state.sqlite3, blobs/, receipts/, proposals/, reports/, exports/
    @classmethod create(case_dir, case_payload) / open(case_dir)
    def close(); def transaction() -> ContextManager   # BEGIN IMMEDIATE; rollback on exception
    # state version & events
    def state_version() -> int
    def append_event(type, payload, *, actor_role, actor_task=None, expected_state_version, idempotency_key, payload_refs=()) -> Event
    # versions
    def new_node(kind, case_id) -> node_id
    def put_version(node_id, payload, *, author_role, author_task=None, author_session=None) -> version_id   # validates payload against kind schema; sets content_hash
    def get_version(version_id) -> dict; def versions_of(node_id) -> list[dict]
    def set_current(node_id, version_id, *, status, applicability="current")
    def current(node_id) -> dict | None                 # {node_id, version_id, status, applicability, kind}
    def find_current(kind, **filters) -> list[dict]     # filters match JSON payload keys via json_extract
    # edges
    def add_edge(from_version, to_version, relation, *, impact_policy=None, reason, proposed_by, status="proposed") -> edge_id
    def set_edge_status(edge_id, status, by)
    def edges_from(version_id, relation=None, status="accepted") / edges_to(...)
    # blobs
    def put_blob(data: bytes) -> sha256; def blob_path(sha256) -> Path
    # ops
    def backup(dest: Path)                              # sqlite3 Connection.backup(); never a file copy
    def export(dest_dir: Path) -> manifest; @classmethod import_(src_dir, case_dir) -> CaseStore   # JSONL tables + blobs; preserves ids and edges
    def integrity_check() -> list[str]                   # PRAGMA integrity_check + referential checks
```
Rules:
- `PRAGMA journal_mode=WAL`, `foreign_keys=ON`, `busy_timeout=5000`. **Refuse** to create a store if `case_dir` resolves under a path containing `Dropbox`, `OneDrive`, `Google Drive`, `iCloud` or is on a network mount (best effort via `os.statvfs` / path check); raise `PolicyError(code="policy", details={"reason": "synced_or_network_filesystem"})`. Tests use `tempfile`.
- Every write goes through `transaction()`. `append_event` checks `expected_state_version == cases.state_version` else `ConflictError`; on success increments `state_version` and inserts the event with `seq` = next integer. Idempotency: same `idempotency_key` with identical payload hash → return the existing event (no new write); with different payload → `ConflictError`.
- `node_versions` rows are never updated or deleted. `node_current` is the only mutable projection. `set_current` records an event `node.current_changed`.
- Schema versioning: table `meta(key, value)` with `schema_version`; `open()` on a newer schema raises; migrations are a list of `(from, to, sql)` applied inside one transaction after `backup()`.
- `export/import_` round trip must preserve every id, version, edge, event and blob hash (AT-15).

DDL tables: `meta`, `cases`, `runs`, `tasks`, `dispatches`, `nodes`, `node_versions`, `node_current`, `edges`, `events`, `receipts`, `impact_queue`, `budgets`. Views: `proposals`, `reviews`, `decisions`, `approvals`, `validations`, `challenges`, `claims`, `requirements`, `sources`, `artifacts` — each `SELECT ... FROM node_versions JOIN node_current ... WHERE kind='<kind>'`. Indexes on `(case_id, kind)`, `(node_id, seq)`, `edges(to_version, relation, status)`, `edges(from_version, relation, status)`, `events(idempotency_key) UNIQUE`, `tasks(run_id, state)`.

## 6. `controller.py`

```python
class Controller:
    def __init__(self, store: CaseStore, registry: Registry, policies: Policies)
    def case_init(project_root: Path, brief: dict) -> case          # brief: objective, protected_constraints[], source_scope[], owner
    def run_start(case_id, workflow: str, mode: budget_mode, *, host: str | None, host_version: str | None) -> run   # state=created→scoped
    def run_plan(run_id, route_plan: dict) -> list[task]              # from routing; tasks in `planned`, deps resolved → `ready`; run→planned
    def task_next(run_id) -> list[task]                                # ready tasks whose deps are accepted, in dependency order
    def task_admit(task_id) -> work_order                              # checks below; task→admitted; budget reserved; returns work-order (envelope)
    def task_attach(task_id, *, host, native_child_id, execution_mode, observed_by) -> dispatch   # task→running
    def task_submit(task_id, response: dict) -> dict                   # validates agent-response; stores artifacts/proposed links as proposals; task→submitted; run→reviewing when all stage tasks submitted
    def task_mark_reviewed(task_id, review_version_id)                 # called by decisions after an eligible review; task→reviewed
    def task_accept(task_id) / task_reject(task_id, reason) / task_block(task_id, reason) / task_needs_input(task_id, question)
    def task_fail(task_id, reason); def task_cancel(task_id)
    def run_status(run_id) -> dict                                     # counts, budget, blockers, next action
    def run_pause/resume/cancel(run_id); def run_complete(run_id) -> dict  # refuses if mandatory gates missing → TransitionError with the list
```
Admission checks (`task_admit`), all enforced, each with its own `PolicyError`/`BudgetExhausted` reason:
1. task state is `ready` and every dependency task is `accepted`;
2. budget: `used_tasks + 1 <= max_worker_tasks`, `running < concurrent_workers`, `used_rounds <= max_challenge_rounds` for challenge-stage tasks; **every attempt and retry counts**; the root orchestrator is not a worker slot; managers/directors/reviewers count when invoked;
3. role exists and its `write_scope` is compatible with the stage (`assigned-worktree` tasks must carry an `output_paths` list under the case's authorized roots; `proposal-only` tasks get only `proposals/` paths);
4. target snapshot recorded (git commit+dirty hash or manifest) for builder/auditor tasks;
5. review requirement: stage `review`/`independence_required` tasks must not be assigned the author role of the artifact under review (looked up from the artifact's `producer_role`);
6. source permissions: `allowed_sources` ⊆ case `source_scope`;
7. wall-clock: `now < run.started_at + policies.budgets.wallclock_limit_s[mode]`.
Reservation is transactional: `budgets.running += 1`, `used_tasks += 1` in the same transaction as the state change; release on submit/fail/cancel/block ("reconciled interruption": a task left `running` past `timeout_s` can be `task_fail(reason="timeout")` by `run_status`'s reconcile step, which releases the slot).

Dispatch identity (`task_attach`): `execution_mode="native"` requires non-empty `native_child_id`; otherwise `PolicyError`. Without an attach, `task_submit` stores `execution_mode` from the response's `actual_execution_metadata` but **downgrades** it: if the response claims `native` and no dispatch row exists with that child id, the stored mode is `sequential` with `observed_by="agent_reported"` and a flag `claimed_native_unobserved=true` (AT-08).

`task_submit`: validates envelope; each `observed_checks` item without `receipt_id` is recorded as `claimed_only=true`; artifacts are stored as `artifact` nodes with status `proposed` (or `implemented_not_verified` for builders); `proposed_links` become `edges` with status `proposed`; `scope_violations` non-empty → task→`blocked` with the violations; `status=needs_input` → task→`needs_input`, run→`needs_input` with the question preserved; `status=blocked` → task→`blocked`; `partial` → stored, task→`submitted`, run cannot complete while partial outputs exist.

Run state machine (exact): `created→scoped→planned→executing→reviewing→completed`; `executing|reviewing → needs_input|blocked|rework → planned`; any non-terminal → `paused|cancelled|failed`; `paused→` the state it left. `run_complete` requires: every non-conditional stage has an `accepted` task (or a `satisfied_by_version_id`), every `review` stage has a review node with `result ∈ {ready, pass}`, every `independence_required` stage has `conflict_check=verified` (else remain blocked with reason `independence_unverified`), no `partial` outputs, no open `needs_input`. Result includes `limitations: [...]` — never a hidden `completed_with_limitations` state.

Task state machine (exact): `planned→ready→admitted→running→submitted→reviewed→accepted`; from `admitted|running|submitted`: `blocked|needs_input|failed|cancelled`; from `reviewed`: `rejected` (→ a new attempt task may be planned; attempt+1). `accepted` is terminal and means the output contract was met, not that a product decision was accepted.

## 7. `lineage.py`

```python
class Lineage:
    def add_source(case_id, payload, *, by) -> (node_id, version_id)
    def add_claim(case_id, payload, *, by) -> ...; def add_requirement(...)
    def propose_link(from_version, to_version, relation, *, impact_policy=None, reason, by) -> edge_id
    def accept_link(edge_id, *, by) / reject_link(edge_id, *, by, reason)
    def contradict(claim_version, contrary_version, *, by) -> edge_id     # adds contradicts edge AND sets claim status 'contested' AND returns a review task request; never flips to unsupported
    def accept_correction(claim_version, *, outcome: supported|unsupported|superseded, by, review_version_id) -> list[impact]
    def impact(changed_version_id) -> list[Impact]                        # reverse BFS over accepted depends_on edges; Impact = {affected_version, path, impact_policy, reason}; deterministic order
    def apply_impact(impacts, *, by) -> list[impact_queue rows]           # per impact_policy: review → queue(state=review_required); invalidate_applicability → node_current.applicability='invalidated' + queue; none → skip. Protected requirements are never retired or invalidated: they are queued as review_required with reason 'protected_requirement_implementation_affected'.
    def mark_historical(validation_version, *, by)                        # applicability historical; result untouched
    def coverage(case_id) -> dict                                          # requirements → implements edges → verifies edges: linked / missing / disputed per requirement
    def missing_lineage(case_id) -> list[dict]                             # artifacts with no depends_on; requirements with no implements; validations with no verifies target
```
Rules: `depends_on` edges require `impact_policy`; other relations must not carry one. A `contradicts` edge never changes status beyond `contested`. `impact()` must include only declared dependents and must report `missing_lineage` separately so the caller cannot mistake the traversal for complete understanding (AT-13).

## 8. `decisions.py` and `policies/`

`policies/authority.json` encodes PRD §10 and architecture §9:
```json

           "manager": {...}, "leader": {...}, "challenger": {...}, "judge": {"adjudicate": "assigned_question"}, 
           "decision_maker": {"accept": "delegation_only"}, "auditor": {"accept": "own_audit_output"}, ...},
 "special": {"human-owner": {"accept": true, "execute": "personally"}},
 "risk_tiers": {"R0": {"autonomous": "recommendation"}, "R1": {"autonomous": "reversible_local_change_with_delegation"},
                "R2": {"autonomous": false, "requires": ["independent_review", "human_acceptance"]},
                "R3": {"autonomous": false, "executable_in_v0_1": false}}}
```
`policies/budgets.json` (modes + `wallclock_limit_s` + `task_timeout_s` default), `policies/risk.json` (keyword triggers that raise risk: deploy, publish, send, pay, delete, production, permission, credential, access; plus "a model cannot lower an explicit policy minimum"), `policies/review-independence.json` (author≠reviewer; same session/child id = conflict; unknown origin = unverified; manager review ≠ independent audit), `policies/data-handling.json` (no telemetry; public export requires allowlist; synthetic-only demos; secrets redaction patterns for receipts).

```python
class Decisions:
    def submit_review(case_id, *, reviewed_refs, reviewer_role, reviewer_session, payload, task_id=None) -> version_id
        # independence: reviewer_role == producer_role of any reviewed artifact → PolicyError('author_cannot_review_own_artifact')
        #               reviewer_session == producer session/child id → conflict_check='conflict' → PolicyError
        #               producer or reviewer session unknown → conflict_check='unverified' (stored; gates requiring independence stay blocked)
        #               manager review of own team's artifact is allowed as *manager review* but is recorded with independent=false
        # result 'pass' requires: every observed_check cited has a receipt_id (else PolicyError 'review_cites_unexecuted_check')
    def open_challenge(case_id, run_id, payload) -> version_id          # enforces max_challenge_rounds for run mode; all five material fields non-empty
    def respond_challenge(challenge_version, response_payload, *, by)   # proposal owner; may create a new proposal version (supersedes edge)
    def submit_ruling(case_id, *, judge_role, payload) -> version_id     # judge types only; payload has criteria, admissible_evidence, findings_per_objection, option_comparison, outcome (ruling_outcome), uncertainty, next_checks, dissent_preserved, scope; a judge may not have authored the proposal; a ruling never changes any artifact/decision status by itself
    def propose_decision(case_id, payload, *, by) -> version_id          # decision status 'proposed'
    def record_user_input(case_id, approval_payload, *, channel) -> version_id   # provenance.attested = (channel == 'host_user_input'); cli/file → attested=false
    def accept_decision(decision_version, *, by, approval_version=None) -> dict
        # by == 'decision-authority': requires approval_version with granted_by='delegation', bound_version_id == decision.proposal_version_id, not revoked, not expired, decision.requested_authority within allowed_decisions; R2+ → PolicyError('human_required') sets status human_required
        # by == 'human-owner': requires approval_version granted_by='human-owner' with provenance.attested == true; attested=false → PolicyError('unattested_human_input') and status stays human_required
        # any role: a judge/manager/specialist → PolicyError('role_cannot_accept')
        # on success: status accepted; event; depends_on edges from decision to its evidence/claims are proposed; dissent preserved verbatim
    def authority_check(role_id, action: propose|review|adjudicate|accept|execute, risk_tier) -> None | PolicyError
    def rounds_used(run_id) -> int
```
No path exists for `execute` on R3. `accept_decision` is not execution permission; the returned dict says so (`"execution_permission": false`).

## 9. `receipts.py`

```python
def snapshot(root: Path, paths: list[Path] | None = None) -> dict      # git: {kind:'git', commit, dirty_diff_sha256, paths}; else {kind:'manifest', manifest_sha256, paths}
def run_command(store, *, task_id, argv: list[str], cwd: Path, timeout_s: int, env_allowlist: list[str] = ("PATH","HOME","LANG","LC_ALL","PYTHONPATH"), test_ids: list[str] = (), redact: list[str] = ()) -> Receipt
```
Rules: `subprocess.run(argv, shell=False, capture_output=True, timeout=…)`; stdout/stderr written to `case_dir/receipts/<receipt_id>.{out,err}`; `timed_out=True` with `exit_status=None` distinguishes timeout from failure (AT-14); `cancelled` set on KeyboardInterrupt; redaction patterns from `policies/data-handling.json` plus `redact` applied to stored logs with `redactions_applied` count; `observation_source="controller"`; the receipt is stored as a row **and** as a `validation`-capable reference; a receipt proves the command ran with that exit status — the receipt payload carries `"proves": "command_exit_status_only"`.

## 10. `routing.py`

```python
class Router:
    def __init__(self, registry, policies)
    def classify(request: str) -> dict        # {workflow_id, confidence (exact|keyword|fallback), action_kind: analysis|proposed_change|local_execution|external_action, risk_tier}
    def evaluate_predicate(name, case_state: CaseState) -> bool   # closed allowlist from registry.workflows.predicates; unknown → ValidationError
    def route(request, *, case_state, mode, explicit_workflow=None, explicit_role=None) -> RoutePlan
```
Algorithm (architecture §8.1): explicit workflow/role wins; else keyword table (each workflow lists trigger phrases drawn from its title/inputs in `policies/routing-keywords.json` — dated, editable); `external_action` keywords force `risk_tier ≥ R3` and the plan carries `human_action_request=true` with no executable stage; for each stage: include if non-conditional, or if its predicate is true; **prune** a stage when a current, accepted artifact of its `artifact` type exists in `case_state` (record `satisfied_by_version_id`) — except `review` and `independence_required` stages, which are never pruned; add manager/director only when the stage list includes them or `consequential_or_disputed`; `explicit_role` yields a one-stage plan for that role with the role's write scope and the case's source scope. Budget check: `len(selected tasks) <= max_worker_tasks` else `budget_check.fits=false` with the overflow count (the plan is still returned; admission enforces). Narrow requests must produce narrow plans (AT-06 tests: "summarize this design" → context-analyst + claim-checker only, no directors/judges).

`CaseState` is a small dataclass built from the store: `current_artifacts: dict[artifact_kind → version_id]`, `has_retrieval`, `protected_scope_touched`, `material_conflicts: int`, `unresolved_dissent: int`, `risk_floor`, `evidence_points_to_code`, `rework_required`, `revalidation_required`, `improvement_has_fixtures`.

## 11. `reporting.py`

Pure functions over the store; output is derived and reproducible (same state → byte-identical output; include no timestamps other than those stored). `case_report(store, fmt="markdown"|"json")` sections: objective; approved requirements (protected flagged); evidence limitations; unresolved questions; active decisions with dissent; implementation status; validation coverage with applicability; impact queue; next action. `run_report(store, run_id)`: proposed vs actual edits; checks run / failed / blocked / claimed-only; execution mode per task; independence status; budget used. `change_impact_report(store, changed_version)`: affected, still valid, missing lineage. `requirement_evidence_rows(...)` for `docs/requirement-evidence.csv` columns in `06` §4.

## 12. `cli.py`

`aipt` with subcommands exactly as architecture §16 (`doctor`, `validate package`, `install`, `uninstall` are M3 stubs that print `not_implemented` and exit 3 in M1). Every command: `--json` output; exit codes 0 ok, 1 AiptError (prints `{"error": {"code", "message", "details"}}`), 2 usage, 3 not implemented. `decision record-user-input --run RUN --record file.json` records with `channel="cli"` → `attested=false`; the help text says the CLI cannot attest human identity. There is no `--role human` flag. `receipt run --task TASK -- <argv>` uses `receipts.run_command`. `case report --format markdown|json`. `eval fixtures --suite core` runs `evals/workflows/*/fixture.json` through the controller in `fixture_replay` mode and prints a per-fixture result labelled `fixture_replay`.

## 14. Addenda fixed before the M1 build

**§5 addendum — operational tables.** `CaseStore` also exposes generic, transaction-scoped row operations for the operational tables `runs`, `tasks`, `dispatches`, `receipts`, `impact_queue`, `budgets`: `insert(table, row: dict) -> key`, `update(table, key, changes: dict, *, expected: dict | None = None)` (raises `ConflictError` when `expected` no longer matches), `get(table, key) -> dict | None`, `query(table, **equals) -> list[dict]` (ordered by rowid). JSON columns are declared in a per-table `JSON_COLUMNS` map and (de)serialised automatically. Only these six tables are allowed; any other name raises `ValueError`. Receipts convenience: `put_receipt(payload) -> receipt_id` (validates against `receipt` schema) and `receipts_for_task(task_id)`.

**§4 addendum — `policies.py`.** Owned by the registry agent. `Policies.load(root) -> Policies` reads every `policies/*.json`, validates `authority.json` against `policy-authority`, and exposes `authority`, `budgets`, `risk`, `review_independence`, `data_handling`, `routing_keywords` as plain dicts plus helpers `mode(name) -> dict`, `risk_at_least(a, b) -> str`, `redaction_patterns() -> list[str]`.

**§10 addendum — `CaseState`.** Defined in `routing.py` with `CaseState.from_store(store, case_id) -> CaseState`; also constructible directly in tests.

**§12 addendum — `fixture_runner.py`.** Owned by the CLI agent. `run_fixture(path, repo_root, work_dir) -> dict` loads `evals/workflows/<name>/fixture.json` (`{workflow, mode, brief, responses: {stage_id: agent-response}, reviews: {stage_id: review}, expect: {...}}`), drives the controller through plan → admit → attach(`execution_mode="fixture_replay"`, `observed_by="controller"`) → submit → review → accept for each stage, and returns `{label: "fixture_replay", passed, failures, run_report}`. Replay output is never labelled live.
